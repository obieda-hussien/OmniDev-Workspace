# Agent execution recovery fixes

These fixes address the reported Android Git/GitHub and browser failures without changing model routing, temperature, tool choice, privilege policy or the P0 finish authority.

- A GitHub URL or repository identity in the objective is remote context, not proof of a checkout under the default Android workspace. The permitted `github_manager` schema is prioritized within the existing bounded surface; remote inspection starts with six ranked candidates instead of the broader initial set, while other permitted tools remain available on demand, and planning/worker prompts explain the remote versus local distinction. Repository access still uses the existing account authorization. Local builds require a verified checkout and a ready developer runtime or an authorized CI/IDE route.
- A pure Git read that cannot start because the app shell lacks `git` is recorded as `TOOL_DEPENDENCY_MISSING`, with its original exit 127 retained. This narrow backend classification requires empty stdout, the exact missing-executable stderr and a pure Git-read command chain. Mixed scripts, writes, partial results, transport errors and unknown effects keep their original failure handling. It is skipped evidence, never success. A real alternative read is still required by P0. P1 records the invocation as cancelled and P2 restores it as skipped.
- `discover_tools` is a runtime control excluded from the ordinary capability index. An exact operation envelope naming discovery now reaches that control directly, including its optional empty query. Exposed P0/P3 controls likewise bypass semantic matching. Unknown and ambiguous names remain non-executing errors.
- Native-capable models are told to use native function calls. Whole-response text envelopes remain a bounded compatibility path; mixed JSON/prose is rejected rather than extracted and executed. No global tool-choice override is added.
- Browser schemas advertise the complete supported action enum in every flavor. `snapshot` is unsupported; page structure uses `get_dom`, and an image uses `screenshot`. Invalid actions fail before WebView/session work. Lite retains its existing restricted action set.
- JSON/fenced provider drafts are withheld from streaming until their complete response can be validated. An interrupted draft is not a tool observation. Checkpoints omit operation payloads, label remaining prose unverified, redact sensitive values, omit private thinking and require verification before retrying uncertain operations. They cannot establish that a page opened or a business action completed.
- REPORT phase wording follows the actual P0 verdict. Incomplete results are never labeled as publishing a verified result. Team workers do not restart from scratch after P0 has exhausted its bounded completion recoveries. Failure propagates through every dependent before readiness is checked, so a blocked dependency chain is not mislabeled as a cycle.

Deterministic domain and real Agent/Team pipeline tests cover the reported call sequences, safe fallback, discovery, browser correction, interrupted streaming, persistence restoration, honest report wording and transitive dependency failure. Existing UI/flavor/security workflows run unchanged. Live Gemini behavior and actual Android shell/browser sessions require device testing; scripted providers exercise protocol behavior without claiming a live-model success rate.

# Chat, keyboard and model selection

The main activity explicitly uses `adjustResize`, matching edge-to-edge Compose IME handling. Chat's Scaffold owns `safeDrawing` insets (including the keyboard); its body applies and consumes that padding exactly once. There is no additional `imePadding` on the transcript/composer container. The composer remains anchored above the keyboard and keeps its existing compact layout in short viewports. A device test opens the real IME twice with an Arabic/English draft, checks the composer-to-keyboard distance, exercises Stop, and verifies that the main activity's merged manifest declares the resize mode.

The conversation header contains history, the conversation/mode title, and New conversation. Settings and Browser are available once, in the history drawer. The composer offers project scope only in execution modes with limited file access. Extended access has no shortcut that unexpectedly opens settings. Browser handoff and links in execution output still work.

The drawer uses the Omni mark, a simple new-conversation action, a filled search field, filters, dated history, and one footer for app navigation. Pin, rename, confirmed bulk deletion, stable message/session identity and saved search/sort behavior remain available. The assistant and welcome state use the cropped launcher artwork rather than a sparkle symbol.

Tools & skills has separate tabs and scroll positions. Each tab offers a compact instruction-loading policy, followed by the relevant controls. Tool-off and search/deep-research dependencies remain enforced. Individual skill selection uses normalized names, supports search, and retains the eligible-skill policy. The sheet explicitly states that changes apply across conversations, matching the existing persistence scope.

Model selection uses one lazy overview and a searchable bottom sheet. Chat, Agent, Coordinator and Worker assignments are distinct. Only connected providers and a configured local model are offered; empty, loading and failed catalogs remain visible with recovery actions. A successful empty catalog does not resurrect stale models. Failed refreshes retain the prior catalog. Copilot refresh uses the authenticated Copilot catalog; catalog IDs are canonicalized once and shared by the registry, picker and persisted assignment. Model details and pricing are optional, and saving/failure state stays inside the picker.

Validation includes catalog identity/availability unit tests and native Compose regressions for real IME positioning, duplicate navigation, history actions, capability dependencies, skill selection, long model catalogs, role identity, saving/failure and setup states. CI exports native captures for the keyboard, drawer, tools/skills and model picker alongside the existing chat previews. A native capture or a new test case is not by itself a measured physical-device performance result; confirm keyboard behavior on the Infinix X689 with its installed keyboard as well.
